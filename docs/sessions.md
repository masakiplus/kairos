# 会話の足跡（Kairos `sessions`）

**このページが会話の足跡（セッション足跡）の書き方の正本である**（2026-11-03 に Notion の「📻 セッション足跡の規約」から移した）。
Claude メモリには「足跡は Kairos の sessions に書く（書き方は `kairos_rules`）」の短い指示だけを置き、具体的な書き方はここと `src/mcp.js` の RULES を読む。
Notion の 📻 Sessions と「セッション足跡の規約」ページは**退役**した。どこかの指示が Notion を指していても、**こちらを優先する**。

## なぜ必要か

クラウドのセッション履歴を後から読む手段は無い（2026-09-04 確認）。定期実行は毎回まっさらなコンテナで動き、他のセッションの中身は見えない。**セッションが自分で書かなければ、何をして何を判断したかは残らない。** 夜の振り返り（Dreamtime）と朝の残課題ハーベスタは、この足跡から「試して駄目だった方法」「持ち越し」を拾う。

## いつ書くか

**実質的な作業か判断があった会話の終わりに 1 件。**

- Kairos・カレンダー・freee・Gmail・スキル・定期タスク・メモリ・リポジトリのどれかを**変えた**
- 何かを**決めた**（採用・却下・方針転換）
- 調べて**分かったことがある**。特に「この方法は使えない」と判明したもの

書かなくてよいのは、単なる調べもの・雑談・何も変えずに終わったやりとり。**迷ったら書かない。**
1 会話 1 件。長い会話で既に書いていてさらに進展があれば、新しく作らず `kairos_update` で既存の行を直す。

🤖 で渡されたタスクの経過・成果はタスクの本文に書く（`kairos_append_body`）。足跡はそれとは別に、会話の振り返りとして 1 件書く。

## どこに書くか

| 対象 | 値 |
| --- | --- |
| DB | Kairos（D1）の `sessions` |
| 書く | MCP の `kairos_create`（`database: "sessions"`）。REST なら `POST /api/data/pages`（data_source_id は `/api/storage/sources`） |
| 読む | `kairos_query`（`database: "sessions"`、新しい順） |

```javascript
kairos_create({
  database: "sessions",
  icon: "🔧",
  fields: {
    "名前": "セッション足跡の書き先を Kairos に統一",
    "日時": "2026-11-04T06:10:00+09:00",
    "サーフェス": "Claude Code",
    "要旨": "…",
    "決めたこと": "…",
    "残課題": "…",
    "うまくいかなかったこと": "…",
    "手戻り": "…",
    "対象スキル": ["tasks-qa-review"],
    "触った領域": ["Tasks", "スキル"],
    "関連タスク": ["<タスクの id>"],
    "関連決定": ["<決定の id>"]
  }
})
```

## 何を書くか

| プロパティ | 書き方 |
| --- | --- |
| **名前** | やったことを体言で短く。日付は入れない（`日時` が持つ） |
| **日時** | 会話が終わった JST の ISO 日時（`+09:00` 付き） |
| **サーフェス** | Cowork / claude.ai / Claude Code / 定期タスク |
| **要旨** | 1〜2 文。結果から書く。手順の列挙にしない |
| **決めたこと** | 確定した判断。提案しただけのものは書かない。無ければ空 |
| **残課題** | 次に持ち越すもの。朝の残課題ハーベスタがここからタスク・未決を起こすので、主語と動詞をはっきり書く（本人の手番なら「（本人）」） |
| **うまくいかなかったこと** | 試して駄目だった方法、撤回した判断。**ここが一番価値が高い**（成果は他にも残るが、失敗はここにしか残らない） |
| **手戻り** | 本人が出力を手で直した・指示をやり直した点。1 件 1 行、事実だけ。迷ったら書く |
| **対象スキル** | 手戻りが起きたスキル名。`手戻り` を書いたら空にしない。選択肢に無い名前はエラーになるので `その他` を選び、名前は `手戻り` に書く |
| **触った領域** | 変えたもの。読んだだけのものは選ばない |
| **関連タスク / 関連決定 / 関連プロジェクト** | 作った・変えたものの id。多いときは代表 5 件まで。`決めたこと` を書いたら `関連決定` は空にしない |

## Decisions との関係

- `決めたこと` のうち**今後の行動や方針を縛るもの**（採用・却下・方針転換・退役・ルール化）は、同じ会話で Decisions にも書き、足跡の `関連決定` で結ぶ。その場限りの作業上の選択は書かない。
- 同じ趣旨の未決があればそれを決着させる。無ければ 状態=決着・決定日=今日・結論=決めたこと・出所=足跡「<名前>」(YYYY-MM-DD) で作り、`期待する結果` と `検証日`（既定は +30 日）も一緒に書く。観測する結果が無いもの（退役・削除）は 検証結果=検証不要。
- `残課題` の判断待ちは足跡の時点では起票しない。翌朝の残課題ハーベスタが拾う。

## 書かないこと

- 会社の業務の内容。業務の話をした会話は足跡ごと書かない
- 認証情報・口座番号・個人を特定する番号
- 会話の転記（各欄は長くても 3 行）
- タスクの代わり（やることは Tasks に起票する）
