# Kairos ⇄ Chronos 同期仕様（タスクの管理・更新の規約）v1

> **読み手は業務端末の AI エージェント（Claude Code など）。** Kairos（個人側・Notion）で固まったタスクの管理・更新の規約を、Chronos（業務側・Obsidian + TaskNotes）へ写すための仕様。作成 2026-10-09・v1。
> 画面のふるまいは [`rules.md`](rules.md)、Notion 側の列は [`notion-schema.md`](notion-schema.md)。食い違ったら `rules.md` が正。

## 0. 統合の形

- **データは統合しない。規約とふるまいを統合する。** 業務データは Notion に載せない、個人データは業務 vault に載せない。Kairos と Chronos は別々の正本を持つ
- **揃えるのは 3 つ**: (1) タスクの状態と日付の意味、(2) 1 タップ操作と AI への受け渡しのふるまい、(3) 夜間棚卸しと一問一答の自律度
- **規約の正本は 1 か所**: `rules.md`（画面のふるまい）と本書（管理・更新の規約）。Chronos 側の `_ops/業務タスク運用規約.md` は本書に準拠し、冒頭に `準拠: chronos-sync v1 (2026-10-09)` と書く
- 業務側だけの差分（§6）は Chronos 側の規約に残す。個人側へ逆輸入したいものは §8 に候補として挙げた

| 個人側の列 | 業務側 | 値と意味 |

## 3. タスクの規約

### 3-1. ステータスと「誰の手番か」

| 誰の手番 | 表し方 | 一覧での扱い |
|---|---|---|
| まだ誰も | `未着手` | 通常 |
| 自分が着手中 | `進行中` | WIP に数える |
| AI が作業中 | `ai_started` が入っている（status とは別） | 全タブの先頭に「処理中」の節 |
| 本人がやらないと進まない | `人対応` | WIP に数える。「処理中」の次に「本人の手番」の節 |
| 外部の返事待ち | `待ち` ＋ `waiting_for` | 今日できる から外す |
| 他の人に任せた | `assignee` | 自分のタブに出さず「委任」タブ。WIP に数えない |

- `人対応` を付ける場面: 発注・支払い・承認、電話・対面・紙、本人にしかできない判断。**本文に「何をすればよいか」を 1 行必ず残す**
- `人対応` のタスクを AI に渡し直したら `進行中` に戻す

### 3-2. 起票

- **本文の先頭 2 行は固定**。その下に出典・手順・経緯を続ける
  - `なぜ: <背景・目的を 1 文>`
  - `何を: <やることを 1 文。留意点があれば同じ行に「留意: …」>`
- 人・AI の対話・自動起票のすべてに適用。タイトルとこの 2 行だけで何のタスクか分かることが基準
- **`due` を空にしない。** 締切が無ければ着手できる日を入れる
- **`scheduled` を入れる条件**（どれか 1 つ）。それ以外は空のまま
  - その日以降でないと手続き・申請ができない
  - 相手の連絡・資料の到着を待ってから動く（日付が読めるなら `scheduled`、読めないなら `待ち`）
  - `due` が 8 日以上先で、早くやっても結果が変わらない（迷ったら `due − 7日`）
- 先行タスクがあるものは `scheduled` を空にする（依存で待たせ、日付で二重に待たせない）
- 起票前に重複を確認する（固有名詞を含む 2 語以上で突合）。同じ用件があれば起票せず、既存の本文に 1 行足す
- PWA のクイック追加はタイトルだけで起票し、残りは夜間棚卸しが補う

### 3-3. 日付の更新

- **延期（明日へ／週末に／来週に／日付を選ぶ）は `scheduled` を動かす操作。`due` は原則動かさない**
- `due` も同じ日へ動かすのは次の 2 つだけ
  - (a) `due` が新しい `scheduled` より前になる（そのままだと期限切れで始まる）
  - (b) `due` ＝ 元の `scheduled`（その日にやる 1 日もの）
- 先の締切は触らない。常に揃えると、来月締切のものを来週へ送ったとき締切が縮む
- 明日へ＝今日＋1 日（土日に落ちたら次の月曜）。来週に＝今日より後の月曜。週末に＝次の土曜（業務では使わないなら出さない）
- 今夜＝`scheduled` を今日の 18:00 の日時にする。**今夜として扱うのは `scheduled` の日付が今日のときだけ**で、翌日以降は普通の今日の節に出す
- ⭐ 今日の3つ＝`mit` に今日の日付。付けるとき `scheduled` が未来なら今日に戻す。4 件以上は見出しで注意。合流するのは「今日やる」タブだけ
- 繰り返しの次回は、`scheduled` を前回の（`due` − `scheduled`）の差で引き継ぐ。前回に `scheduled` が無ければ `scheduled` ＝ `due`
- 親タスクの `due` を動かしたら、同じ操作の中で `due` を持つ未完了の子も同じ日に揃える（親が正本。`due` が空の子には付けない）
- 締切だけを動かすボタンは作らない（締切の変更は AI との対話かノートで）

### 3-4. 完了・見送り・重複

- **完了は 4 点を同じ書き込みで**: `status: 完了`・`completedDate`＝今日・`waiting_for` を空に・根拠を 1 行。`ai_started` と `ai_mode` も同時に空にする
- 根拠が書けないなら完了ではなく `要判断`
- **見送りで完了**: やらないと決めたものも完了として閉じる。根拠は `見送り (YYYY-MM-DD, <経路>)`
- **重複で完了**: 削除しない。残すのは古い方。新しい方にしか無い情報は先に古い方へ写す。根拠は `重複のため完了 (YYYY-MM-DD, <経路>, 相手: <残す方の名前>)`
- **締切が実在するものを、締切の前に一覧から消さない。** 「どうするかが決まった」だけなら完了にせず `待ち` にして `due` を残す。どうしても完了にするなら、同じ操作で締切日を `due` にした後継タスクを 1 件起こす
- 後続を完了にするとき未完了の先行が残っていたら、その場で「一緒に完了／見送りで完了／そのまま残す」を聞く。黙って先行を閉じない
- **本人が入れた完了を自動化側が外さない。** 無人便は完了を取り消さない
- 根拠の書式は `<種別> (日付, 経路): メモ`。経路は `PWA`・スキル名・`対話` のどれか。**書く場所は §7 の未決 1**

### 3-5. 先行タスク（依存）

- 判定: 未完了の先行が 1 件以上 → **先行待ち**。優先順位は 先行待ち ＞ 待機（`scheduled` が未来）＞ 着手可。見るのは直接の先行だけ（完了が順に伝わるので連鎖は成立する）
- 先行待ちのタスク自体は操作不可（先行から順に完了するか、チェーンごと AI に任せる）
- **依存は自動で結ばない。** 結ぶのは人（PWA の先行ピッカー。同じ PJ の未完了から複数選択）か、夜間棚卸しの提案を人が見直しで確定したときだけ。誤った依存は後続を操作不能にする
- 自分自身と循環は拒否する
- 未完了 3 件以上で依存が 0 本の PJ には「順番未整理」を表示する
- PJ の見出しからタスクを足したとき、その PJ に他の未完了があれば「先行を選ぶ」を出す
- 「後続の `due` ＜ 先行の `due`」は矛盾として赤で出し、「期日を先行に揃える」を 1 タップで
- 表示: 先行待ちは 今日やる／今日できる に出さない。`due` が今日以前のものだけ 今日やる の末尾に薄く出す。PJ別 では全部出す
- **順送り実行（AI・スキル共通）**: あるタスクを進めるよう頼まれたら、必ず先に先行を確認する
  1. 先行を再帰的に辿り、未完了だけを先行が先になる順に並べる（深さ 10 まで。循環は止めて知らせる）
  2. 「B をやるには A1 → A2 が先。順に進める？」と見せる
  3. 先行を 1 件ずつ実行し、終えるたびに §3-4 の完了処理。判断が要る・人の手が要る・失敗した時点で止まり、どこまで進んだかを報告する
  4. 先行が全部終わって初めて B に手を付ける

### 3-6. AI への受け渡し

- **渡すとき（PWA 側）**: `ai_started`＝今、`ai_mode`＝実行 or 更新 を書く。`人対応` だったら `進行中` に戻す。`ai_session` があればそのセッションの続きで始め、新しく始めるときは `ai_session` を空にする
- **文面はタスク名で始め、ノートへのパス（個人側はページ URL）を含める。**「処理開始の印が立っている。終わるときに外す」の一文を入れる
- **受けた AI は最初の手で `ai_session` を書く**（書き忘れても実害はない。戻り道が無くなるだけ）
- **終わり方は 3 つだけ。どれでも `ai_started` と `ai_mode` を空にする**
  - 完了 → §3-4 の完了処理と同じ書き込みで外す
  - 判断待ち・人の手が要るで停止 → 同じ書き込みで `status: 人対応`、本文に「何をすればよいか」を 1 行
  - 失敗 → 外して、どこまで進んだかを本文に 1 行
- 外し忘れの安全網: PWA は開始から **2 時間** で処理中の表示をやめる（値は残す）。夜間棚卸しが **24 時間** より前の印を空にする
- 処理中でも人は完了・延期できる。完了だけは「AI が処理中。それでも？」を一度聞く
- AI ができないこと（発注・支払い・送信など会社のルールで人がやること）に当たったら、やろうとせず `人対応` で止まる

### 3-7. 委任

- 個人側: `担当` が入っていれば委任中。自分のタブ（今日やる／今日できる／PJ別）に出さず「委任」タブに担当ごとに並べる。期日とステータスは触らない。完了は自分が入れる
- 委任中のタスクは、夜間の「期限切れを今日へ置き直す」処理の対象外（任せた相手の約束の日を機械が塗り替えない）。件数だけ報告する
- **業務側は `waiting_for` と役割が重なるので、§7 の未決 2 を決めてから実装する**

### 3-8. 一覧の条件と WIP

| タブ | 条件 |
|---|---|
| 今日やる | `due` ≦ 今日 かつ 着手可。⭐ はここにだけ合流 |
| 今日できる | 着手可・`待ち` でない・`due` が 1〜7 日後 または 空 |
| 着手中 | `進行中`・`人対応`（＋処理中）の未完了。待機は外す |
| 待ち（業務側） | `status: 待ち`。相手と経過営業日 |
| PJ別 | PJ に属する未完了を全部（待機・待ち・先行待ちも） |
| 委任 | `assignee` が入っているもの |

- 処理中（`ai_started` が 2 時間以内）は、タブの条件に関係なく全タブの先頭に出す
- WIP＝`進行中`＋`人対応` の未完了（委任中と待機を除く）。**上限は既定 10**。超えたらヘッダーに警告
- 1 タップ操作には必ず取り消しを付ける（操作前の値を控え、渡された項目だけ戻す。AI に渡す操作は対象外）
- 規約のロジックはサーバー側（個人側は Worker、業務側は `server.py`）に置き、画面には置かない。編集画面は作らない

## 4. 棚卸し・判断・役割

### 4-1. 夜間棚卸し（無人）の検査

原則は「機械的に直せるものは直し、迷うものは提案に留める。無人なので質問しない。本人の完了は外さない」。自動変更は 1 回 25 件まで。

| 検査 | 自動でやること | キット以降 |
|---|---|---|
| 日付なし・ラベルなし・塩漬け | 明確なら埋める。迷うなら `SchedReview` ＋本文に提案 1 行 | |
| 期限切れ（B） | 今日へ置き直す。**委任中と先行待ちは動かさない** | 条件追加 |
| 重複（E） | 提案まで。自動で完了にしない | |
| 片肺完了（F） | status と completedDate の不整合を正規化。完了は外さない | |
| 停滞判断（G） | Decisions に提案中で起票（1 回 5 件）。**問いの形に書けないもの・期日と段取りが既に書いてあるものは起こさない** | フィルター 2 つ |
| 親子の期日不一致（H） | 子を親に揃える | |
| Projects 整合（I） | 役割リンク漏れと逆向き不整合は直す。クローズ候補は Decisions へ（1 回 3 件） | |
| 「正常化」と書いて閉じた件の再発（J） | 未完了側に `要判断` ＋ 1 行（1 回 3 件） | |
| 依存（M） | 循環は警告。先行待ちで期限切れなら先頭の先行を今日やるに上げる提案。先行待ち 30 日超は Decisions へ | 新規 |
| 処理中の印の外し忘れ（N） | 24 時間より前の `ai_started` を空にする | 新規 |
| 「なぜ／何を」が無い（O） | 読める範囲で 2 行を書き足す（既存の文は消さない。1 回 25 件） | 新規 |
| 検証待ちの決定（P） | 件数を報告するだけ | 新規 |
| 開始日なしの待ちタスク（Q） | 待ち条件が日付で読めるものだけ、開始日を**提案**（自動では埋めない。1 回 10 件） | 新規 |
| 依存案・日程案 | 同じ PJ の未完了から依存と開始日・期日を提案し、Decisions に種別 `依存案`／`日程案` で起票。人が見直しで確定 | 新規 |
| 待ち超過（W・業務側のみ） | 5 営業日で催促を提案。メールは下書きまで | |

個人側にあって業務側に要らないもの: アイコン補完（K）、習慣の提案（L）。

### 4-2. Decisions

- 状態は `提案中` → `提示済み` → `決着`。**決着は最終**。前提が変わったら状態を戻さず新しいノートを起こし、出所に旧ノートを書く
- **無人便は提案中まで。決着は本人が一問一答（1 ターン 1 問）で決める。** 例外は、本人が対話の中で既に決めたことの記録だけ
- 決着と同じ書き込みで **`期待する結果`**（観測できる形で 1〜2 文）と **`検証日`**（既定は決定日＋30 日、時間のかかるものは＋90 日）を書く
- 検証日が来たら 1 件 1 問で `検証結果`（当たり／外れ／部分的／検証不要）と `学び`（次に何を変えるかを 1 文）を埋める。「まだ判断できない」は検証日を延ばす（1 件 2 回まで。3 回目は検証不要で閉じる）
- 見直しカードの種類: 未決／PJ クローズ候補／繰越 3 回以上／検証待ち／依存の提案（結ぶ・結ぶだけ・結ばない）／日程の提案（この日程にする・置かない）

### 4-3. 統合棚卸し

- 順番は Decisions → Tasks → Projects → Roles
- **週 2 回の定期実行**（個人側は水・日）。無人で直せる分まで済ませ、1 問目を出して待つ。本人が開いて一問一答を続ける。役割の週次目標はそのうち 1 回（業務側は月曜朝）で決める

### 4-4. 今週の石

- 役割ごとに週 1 件。**置くのは「予定に入れなければ起きない」かつ「AI に渡せない」ものだけ。** それ以外は普通のタスクとして流す（実績ベースで小石になるのを防ぐ）
- 役割ノートへの書式は `〜M/D：<タスク名> → <タスクへのリンク>`

## 5. 写さないもの（Notion 固有の事情）

- view / rows / SQL の使い分けと利用上限、UTC と JST のずれ、機械が読む固定ビュー
- 完了チェック・完了日・ステータスの 3 列が別々にある事情（業務側は `status` と `completedDate`）
- 繰り返しの次回を作る自前スクリプト（TaskNotes の `recurrence` で足りる）
- アイコンの取得と補完、家族カレンダー、チャット通知、チャット URL へのディープリンク、習慣（Habits）

## 6. 業務側だけの規約（Chronos に残す）

- `waiting_for` と待ち超過（W）
- 書く前にファイルの mtime を確かめ、変わっていれば 409 で拒否する（Obsidian 側の編集と衝突させない）
- ローカル PWA は 127.0.0.1 のみ。外部接続はメール／予定表のコネクタだけ。メール送信は自分宛の朝夕便だけ
- 足跡・レビュー・メール便に、顧客名や金額をタスク名以上の粒度で書かない
- 役割の年次見直しは期初

## 7. 未決（本人が決めること）

1. **根拠 1 行をどこに書くか。** 個人側は PWA が説明の先頭、AI とスキルがページ本文と 2 通りある。業務側は説明と本文の区別が無いので、**「なぜ／何を」の 2 行は先頭に固定し、根拠・待ち・提案の 1 行は本文末尾の `## 経過` 節に日付つきで足す** のを推奨
2. **委任の表し方。** (a) `assignee` を足して「委任」タブを作る（個人側と同じ形）、(b) `待ち` ＋ `waiting_for` に寄せて「待ち」タブで見る。相手に催促する前提なら (b)、任せきりで結果だけ受け取るなら (a)
3. **`ai_session` に何を入れるか。** Claude Code のセッション ID を推奨。取れない版なら空のまま運用する
4. **依存フィールドの名前。** TaskNotes に依存の機能があればそれに合わせる。無ければ `blockedBy` に wikilink の list
5. **WIP 上限。** 個人側は 10。業務側も同じでよいか

## 8. 個人側へ逆輸入する候補

- `waiting_for`（誰に・何を）を独立した項目にする。個人側は説明の先頭に `待ち (日付, PWA): 相手` と書いているだけで、経過日数を機械で数えにくい
- 待ち超過の検出（W）
- 書き込み前の更新時刻チェック

## 9. 受け入れ確認（業務端末で実装後に試す）

| 操作 | 期待する結果 |
|---|---|
| `due` が来月・`scheduled` が今日のタスクを「来週に」 | `scheduled` だけ次の月曜。`due` は変わらない |
| `due`＝`scheduled`＝今日のタスクを「明日へ」（金曜） | 両方とも次の月曜 |
| `due` が昨日のタスクを「明日へ」 | 両方とも明日 |
| 未完了の先行があるタスク | 今日やる／今日できる に出ない。`due` が今日以前なら 今日やる の末尾に薄く出る |
| 先行を完了 | 後続が何も書き換えずに着手可になる |
| 後続を先に完了 | 3 択（一緒に完了／見送り／残す）が出る |
| A→B→A の依存を結ぼうとする | 拒否される |
| AI に渡す | `ai_started` と `ai_mode` が入り、全タブの先頭に出る |
| AI が人の手が要るで停止 | `ai_started` が空・`status: 人対応`・本文に次の手が 1 行 |
| `ai_started` が 3 時間前のまま | 処理中の表示は消える（値は残る）。翌朝の棚卸し後は 24 時間超のものだけ空 |
| 重複で完了 | 削除されず完了。根拠に相手の名前 |
| 締切が来月の申請タスクを「方針が決まった」で閉じようとする | 完了にならず `待ち`、または後継タスクが同時に起きる |
| 進行中＋人対応が 11 件 | ヘッダーに WIP 警告 |
| 昨日「今夜」にしたタスク | 今夜の節ではなく普通の今日の節に出る |
| 1 タップ操作のあと取り消し | 操作前の値に戻る |
