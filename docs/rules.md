# 運用規約（Kairos が守る振る舞い）

> D1移行後は、本文中の「Notionに記録・更新」はKairosのD1に記録・更新する読み替えになる。業務上の完了・日程・依存・役割の規約は維持する。Notionの旧コピーや未移行の外部ジョブからD1への自動同期は行わない。接続先は `docs/d1-cutover.md` を参照。

Kairos の設計原則は **「規約のロジックは Worker（`src/index.js`）に一本化し、画面は表示と 1 タップだけ」**。
同じ Notion を他のツール（夜間棚卸し、対話スキル、別端末のタスク環境）から触るときも、ここに書いた振る舞いに合わせれば矛盾しない。
別環境（Obsidian + TaskNotes の業務タスク環境など）へ規約を写すときの対応表と作業リストは [`chronos-sync.md`](chronos-sync.md)。

## 1. 役割分担

- **人 ＝ 判断、AI ＝ 実行、Notion ＝ 記録**。Kairos は「一覧を見て、その場で終わる操作だけを押す」層。
- 思考が要るもの（時間調整・実行・内容の書き換え）は「🤖 進めてもらう」「✏️ 更新してもらう」で AI チャットに投げる。文面は **タスク名で始め、ページ URL を含める**。
- **成果・決定事項はタスクの本文（Notion ページ本文）に詳しく書く。** 関連するノート・ファイル・外部 URL は本文にリンクで並べる（進行中も同様）。Kairos は説明と本文からリンクを集めてシートの 概要 に「🔗 関連」チップとして出す（Notion はリーダーで、Drive・Gmail・Web はそのまま開く）。🤖 に渡す文面にもこの規約を含める。
- タスクの編集画面は作らない。Roles / Projects の編集画面も作らない（Kairos が書くのは Roles の `今週の目標` と Projects の `ステータス`・`名前`・`対応ゴール`・`完了条件`・`役割` だけ。名前と完了条件は人が決めた内容を書き写すときだけ変える。画面からは編集しない）。
- **過去に AI で扱ったタスク（`AIセッション` あり）は、進める／更新する もそのセッションの続きで始める。** 既存チャットには文面を URL で渡せないので、Kairos が文面をクリップボードに入れ、人が貼って送る。新しいチャットで始めたいときはシートの「新しいチャットで始める」。`AIセッション` は完了しても消さない（後から経緯を辿れるように）。

## 2. 完了・見送り・重複

- **完了 ＝ 3 点セット**: `完了`✓ ＋ `完了日`＝今日 ＋ `ステータス`＝完了。どれか欠けると「片肺完了」で棚卸しが拾う。
- 完了時に **理由を 1 行**添えられる。`説明` の先頭に `完了 (YYYY-MM-DD, PWA): メモ`。
- **見送りで完了** ＝「やらないと決めた」も完了として閉じる（未完了のまま残すと棚卸しが拾い続ける）。`説明` の先頭に `見送り (日付, PWA)`。ラベルは増やさない。
- **重複で完了** ＝ 相手のタスク名を任意で残す: `重複のため完了 (日付, PWA, 相手: …)`。
- 完了したら 🤖 処理中の印（`AI処理開始`・`AI処理種別`）は外す。
- 後続を完了したとき未完了の先行が残っていれば、その場で「一緒に完了／見送り／残す」を聞く。自動では触らない。

## 3. 日付（延期は開始日を動かす）

- **明日へ／週末に／来週に／開始日を選ぶ はすべて `開始日` を動かす操作。** 期日は原則動かさない。
- 例外として期日も同じ日へ動かすのは次の 2 つだけ: (a) 期日が新しい開始日より前（そのままだと期限切れで始まる）、(b) 期日＝元の開始日（「その日にやる」1 日タスク）。先の締切は触らない（常に揃えると、来月締切のタスクを週末に送ったとき締切が縮む）。
- 明日へ ＝ 今日＋1 日、土日に落ちたら次の月曜。週末に ＝ 次の土曜（今日が土なら明日、日なら来週の土曜）。来週に ＝ 今日より後の月曜。
- **今夜にする** ＝ `開始日` を「今日 18:00」の日時にする。列は増やさない。翌日には自然に普通の「今日」に戻る。
- **🌅 早朝向き** ＝ `実行環境` に `早朝`。定義: 家にいて家族は起きていない（相談は不可・**準備はできる**）、大きな音は出せない、急がず 1 件に時間をかけられる。**22:00〜05:59**（2026-10-15 に 04:00〜06:59 から拡張。深夜と早朝を分けない）に開くと 今日やる・今日できる の先頭に「🌅 早朝にゆっくり」節（早朝タグ付きで着手可のもの。優先度 → ⭐ → 期日 の順）。昼間は節を作らない。付け外しはシートの「早朝向きにする」(↩ 対応)。自動では付けない。
- **⭐ 今日の3つ**（MIT）＝ `今日の3つ` に今日の日付。翌日に自然に外れる。⭐ を付けるとき開始日が未来なら今日に戻す（今日やると決めたのだから）。4 件以上は見出しで注意。

## 4. 一覧の条件

| タブ | 条件 |
|---|---|
| 今日やる | 期日 ≦ 今日、着手可（開始日 ≦ 今日、先行待ちでない）。先行待ちは期日が来ているものだけ末尾に薄く |
| 今日できる | 着手可、`待ち` でない、期日が 1〜7 日後 または 日付なし。節は「期日まで 3 日以内／今週中／日付なし」 |
| スマホで | 着手可、実行環境に `スマホ`（2026-10-15 まで `iPhone`）か `電話`。節は「📞 電話する／📱 スマホで片付ける」 |
| 着手中 | `進行中`・`人対応`（＋🤖 処理中）の未完了。開始日が先（待機）のものは外す。先行待ちは出す。WIP 警告の行から開く |
| PJ別 | PJ に属する未完了を全部（待機・待ち・先行待ちも） |
| 委任 | `担当` が入っているもの。委任中は自分のタブに出さず WIP にも数えない |

- 行の状況タグは、いまの状況と合わない軸だけ出す（合っているタグはノイズ）。🌅 早朝はいつも出す。
- 🌅 早朝向きは **期日に関係なく** 今日できる に渡る。静かな時間（深夜・早朝）は 🌅 節に全部並び、昼間は期日が 7 日より先のものを出さない（2026-10-15）。付けるのは本人（シート）と夜間棚卸しの早朝案（中身から LLM が判定し `早朝` を足す。外すのはシートで）。
- 🤖 処理中（`AI処理開始` が 2 時間以内）は全タブの先頭に独立した節。
- ⭐ 今日の3つ の合流は 今日やる だけ。他のタブはそのタブの条件を満たすものだけ。
- 式の結果が遅れることがあるので、素の日付からも同じ判定をかけ直す。
- Notion のページングで同じページが 2 回返ることがある。id で重複を落とす。

## 4-2. いまの状況（コンテキスト）

- `実行環境` は 4 つの軸で読む: **📍 場所**（自宅／職場／外出）、**🧰 道具**（Mac／スマホ／電話／紙・郵送）、**⏰ 時間帯**（早朝）、**👥 相手**（「〜と」で終わる選択肢。例: 家族の名前＋「と」＝その人との相談・了承・一緒の作業が要る）。
- 👥 相手の選択肢は Worker が Notion のスキーマから読む（名前をコードに書かない）。既定は **自宅にいる（早朝を除く）＝全員一緒、外出・職場・早朝＝誰もいない**。一緒に出かけているときはチップから手で足す。場所を手で変えると 👥 も既定に合わせ直る。
- 判定は 1 行: **タグが付いている軸ごとに、1 つ以上が今の状況と合えば「いまできる」。タグが無い軸は不問。**
- **🌅 早朝（22:00〜05:59）は「静かな時間」**: 電話・紙・郵送・一緒にいる人は無しとして扱い、それが要るタスクは「💤 いまはできない」に沈む。早朝向きタグはその間ずっと先頭節「🌅 早朝にゆっくり」に出る（2026-10-15: 深夜と早朝の区別をやめた）。
- 今の状況はヘッダーのチップ 1 つで持つ。場所は **📍 今の居場所**（スマホの位置から外部の受信 Worker が書く Notion ページ。`PRESENCE_PAGE_ID`）の区分を第一にし（伊豆 は 外出 扱い）、最終受信が 3 時間より古いか取れなければ 曜日・時刻（平日 9〜19 時は職場、水曜は在宅）に落ちる。道具は端末（Mac か スマホ）、時間帯は時刻。チップに出どころを添える（位置／曜日）。タップで手で変えられ、手で変えた値は推定が変わるまで有効。
- 合わないタスクは 今日やる／今日できる／スマホで の末尾「💤 いまはできない（理由）」に **沈める**。隠さない（期限切れを見失わないため）。バッジの件数も変えない。⭐ 今日の3つ と 🧔 人対応 も同じ基準で沈める（例外は 🤖 処理中 と 先行待ち だけ）。
- タスク側の付け外しはシートの「📍 できる状況」（場所 3・道具 4・相手・早朝）を 1 タップ。タグが付いた軸だけ条件になり、空＝どこでも。↩ 対応。自動では付けない。
- タブは増やさない。「スマホで」はこの仕組みが落ち着いたらチップのプリセットに吸収する。

## 5. 先行タスク（依存）

- `先行未完了数 > 0` ＝ 先行待ち。先行待ちのタスク自体の操作は不可（先行から順に完了するか、チェーンごと AI に任せる）。
- **依存は自動では結ばない**。結ぶのは人（シートの「先行タスクを選ぶ」、同じ PJ の未完了から複数選択）か、夜間棚卸しの提案を人が見直しタブで確定したとき。間違った依存は後続を操作不能にする。
- 自分自身・循環は拒否。
- 未完了 3 件以上で依存 0 本の PJ には「順番未整理」バッジ。
- つながり（ガント／依存順）は「後続の期日 ＜ 先行の期日」の矛盾を赤で出し、「期日を先行に揃える」を 1 タップで。

## 6. WIP と状態

- `進行中`＋`人対応` の未完了（委任中と開始日が先のものを除く）を WIP として数え、上限（既定 10）を超えたらヘッダーに警告。
- `人対応` ＝ AI が「人の手が要る」で止めた印。人が手で付けるときは 🤖 の印も外す。人対応 を 🤖 で渡し直すと `進行中` に戻る。
- `待ち` ＝ GTD の Waiting For。相手を 1 行聞き、`説明` の先頭に `待ち (日付, PWA): 相手`。

## 7. 追加

- タイトルだけで起票。アイコン必須（既定 📥）、エリア既定（`QUICK_ADD_AREA`）、ソース `手動`、開始日 今日、実行環境は **いまの状況**（端末＝Mac か スマホ、＋場所）。残りは夜間の棚卸しが補完する（実行環境が空のタスクには夜間が最小限のタグを付ける）。
- PJ 見出しから足したときは `関連プロジェクト` を付け、その PJ に他の未完了があれば「先行を選ぶ」ボタンを出す。

## 7-2. 📄 リーダー（Notion ページをアプリを切り替えずに読む）

- シートの 概要 にある **関連チップ（決定・PJ）** と、説明・本文の **Notion リンク**（notion.so／app.notion.com の 32 桁 id）は、Kairos の中のリーダーで開く（`GET /api/page/:id`。読み取り専用、見出し・箇条書き・チェック・引用・コールアウト・コード・子ページ・画像。表と DB は Notion で）。子ページはリーダーの中で続けて開け、戻るで前のページ → シートに戻る。
- 外部サイトのリンクはそのまま（Android の PWA はカスタムタブで開き、戻るで Kairos に戻る）。`iframe` 埋め込みは大半のサイトが拒むので作らない。

## 8. 取り消し

- 1 タップ操作には必ず ↩ を付ける。操作前の値（完了・期日・開始日・ステータス・担当・説明・AI処理開始・関連プロジェクト・先行タスク）を端末に控え、`POST /api/tasks/:id/restore` で渡された列だけ戻す。最大 20 件、端末ごと。
- 🤖 に投げる操作と「未完了に戻す」は対象外。

## 9. 決める（一問一答カード。旧「見直し」）

機械的に作れる問いだけを 1 問 1 画面で出し、理由が要るものは AI チャットへ逃がす。カードは **種類の帯（🧠 未決／📁 PJ を閉じる？／↻ 繰り越し／🔍 答え合わせ／🔁 習慣／⏭ 順番の提案／📅 日程の提案）＋「なぜ今か」1 行＋定型の問い（「〈対象〉を、どうする？」）＋動詞で揃えた選択肢（AI 推奨は 1 番上を太く、理由を添える）**。依存案・日程案は「① → ②」「開始 10/13 → 10/19（+6 日）」の図で見せ、機械行は出さない。先頭の種類チップで 1 種類だけ連続で答えられ、「この種類は後で」で端末内で後回しにできる（チップから戻せる）。答えた直後に次の問いがスライドで入る。

| 種類 | 元 | 答え |
|---|---|---|
| 未決 | Decisions 状態≠決着・開始日が来ている | 着手する／棚上げ／やめる → 決着（決定・決定日・結論）＋**次の動き**（下）。今は決めない → 提示済み＋提示日 |
| PJ クローズ候補 | 未完了 0・完了 1 以上の PJ | クローズ（ステータス＝完了＋Decisions に決着行）／まだ続ける（次のアクションを足す） |
| 繰越 3 回以上 | 説明の `[棚卸し滞留 繰越N回` | 見送りで完了／⭐ 今日の3つ／来週に |
| 検証待ち | 決着・検証日≦今日・検証結果 空 | 当たり／外れ／部分的／検証不要（メモは 学び へ） |
| 習慣 | 計測方法 手動／半自動 で今日（週N は日曜に今週）の記録なし。`判定キーワード` があれば先に完了タスクから機械判定し、達成なら聞かずに Habit Log へ `kairos` で記録 | やった／やらなかった → Habit Log |
| 依存の提案 | 種別 `依存案` | 結ぶ（日程も置く）／結ぶだけ／結ばない |
| 日程の提案 | 種別 `日程案` | この日程にする／置かない |

未決を決着させるときは、決着だけで終わらせない（2026-10-11。「着手する」なのにタスクが無い・「やめる」なのにタスクが残る・「棚上げ」が二度と聞かれない、を防ぐ）。

| 答え | Decisions | Tasks |
|---|---|---|
| 着手する | 期待する結果＝「タスクが期日までに完了」、検証日＝決定日＋30 日 | 未完了の関連タスクがあればそれが次の一手。無ければ 1 件起票して `決定` で結ぶ（名前はメモ、無ければ「「〜」を進める」。期日＝7 日後） |
| 棚上げ | **見直し日が必須**。検証日＝見直し日（その日に検証待ちとしてまた出る） | 未完了の関連タスクの開始日を見直し日へ（期日は延期と同じ条件で） |
| やめる | 検証結果＝検証不要 | 未完了の関連タスクを見送りで完了（説明の先頭に根拠 1 行） |

- 期限が実在するタスク（種類＝支払い・手続き で期日が今日以降）は、棚上げ・やめるでも動かさず残す。
- 依存案・日程案の確定は観測する結果が無いので 検証結果＝検証不要 を同時に書く。
- 決着は ↩ で戻せる（`POST /api/review/decision/:id/undo`。起票したタスクはゴミ箱、閉じた・送ったタスクは元の値、決定は未決へ）。

## 10. やらないこと

- タスクの編集画面、Roles / Projects の編集画面、Habits の定義変更
- 期日だけを動かす延期ボタン（締切は AI か Notion で）
- ネイティブアプリ化・通知常駐（欲しくなったら Decisions に起票して再検討）

## 11. 公開前の検査

- `node --check` は ESM の `.js` を素通りする。**`.mjs` に写してから検査**する。
- 秘密はファイルに書かない。`NOTION_TOKEN` / `APP_TOKEN` は Worker の secret。
- `sw.txt` の `kairos-vNN` を上げないと端末のキャッシュが入れ替わらない。
