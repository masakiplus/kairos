# 運用規約（Kairos が守る振る舞い）

Kairos の設計原則は **「規約のロジックは Worker（`src/index.js`）に一本化し、画面は表示と 1 タップだけ」**。
同じ Notion を他のツール（夜間棚卸し、対話スキル、別端末のタスク環境）から触るときも、ここに書いた振る舞いに合わせれば矛盾しない。

## 1. 役割分担

- **人 ＝ 判断、AI ＝ 実行、Notion ＝ 記録**。Kairos は「一覧を見て、その場で終わる操作だけを押す」層。
- 思考が要るもの（時間調整・実行・内容の書き換え）は「🤖 進めてもらう」「✏️ 更新してもらう」で AI チャットに投げる。文面は **タスク名で始め、ページ URL を含める**。
- タスクの編集画面は作らない。Roles / Projects の編集画面も作らない（Kairos が書くのは Roles の `今週の目標` と Projects の `ステータス` だけ）。
- **過去に AI で扱ったタスク（`AIセッション` あり）は、進める／更新する もそのセッションの続きで始める。** 既存チャットには文面を URL で渡せないので、Kairos が文面をクリップボードに入れ、人が貼って送る。新しいチャットで始めたいときはシートの「新しいチャットで始める」。`AIセッション` は完了しても消さない（後から経緯を辿れるように）。

## 2. 完了・見送り・重複

- **完了 ＝ 3 点セット**: `完了`✓ ＋ `完了日`＝今日 ＋ `ステータス`＝完了。どれか欠けると「片肺完了」で棚卸しが拾う。
- 完了時に **理由を 1 行**添えられる。`説明` の先頭に `完了 (YYYY-MM-DD, PWA): メモ`。
- **見送りで完了** ＝「やらないと決めた」も完了として閉じる（未完了のまま残すと棚卸しが拾い続ける）。`説明` の先頭に `見送り (日付, PWA)`。ラベルは増やさない。
- **重複で完了** ＝ 相手のタスク名を任意で残す: `重複のため完了 (日付, PWA, 相手: …)`。
- 完了したら 🤖 処理中の印（`AI処理開始`・`AI処理種別`）は外す。
- 後続を完了したとき未完了の先行が残っていれば、その場で「一緒に完了／見送り／残す」を聞く。自動では触らない。

## 3. 日付（延期は開始日を動かす）

- **明日へ／週末に／来週に／開始日を選ぶ はすべて `開始日` を動かす操作。** 期日は原則動かさない。
- 例外として期日も同じ日へ動かすのは次の 2 つだけ: (a) 期日が新しい開始日より前（そのままだと期限切れで始まる）、(b) 期日＝元の開始日（「その日にやる」1 日タスク）。先の締切は触らない（常に揃えると、来月締切のタスクを週末に送ったとき締切が縮む）。
- 明日へ ＝ 今日＋1 日、土日に落ちたら次の月曜。週末に ＝ 次の土曜（今日が土なら明日、日なら来週の土曜）。来週に ＝ 今日より後の月曜。
- **今夜にする** ＝ `開始日` を「今日 18:00」の日時にする。列は増やさない。翌日には自然に普通の「今日」に戻る。
- **⭐ 今日の3つ**（MIT）＝ `今日の3つ` に今日の日付。翌日に自然に外れる。⭐ を付けるとき開始日が未来なら今日に戻す（今日やると決めたのだから）。4 件以上は見出しで注意。

## 4. 一覧の条件

| タブ | 条件 |
|---|---|
| 今日やる | 期日 ≦ 今日、着手可（開始日 ≦ 今日、先行待ちでない）。先行待ちは期日が来ているものだけ末尾に薄く |
| 今日できる | 着手可、`待ち` でない、期日が 1〜7 日後 または 日付なし |
| スマホで | 着手可、実行環境に `iPhone` か `電話` |
| 着手中 | `進行中`・`人対応`（＋🤖 処理中）の未完了。開始日が先（待機）のものは外す。先行待ちは出す。WIP 警告の行から開く |
| PJ別 | PJ に属する未完了を全部（待機・待ち・先行待ちも） |
| 委任 | `担当` が入っているもの。委任中は自分のタブに出さず WIP にも数えない |

- 🤖 処理中（`AI処理開始` が 2 時間以内）は全タブの先頭に独立した節。
- ⭐ 今日の3つ の合流は 今日やる だけ。他のタブはそのタブの条件を満たすものだけ。
- 式の結果が遅れることがあるので、素の日付からも同じ判定をかけ直す。
- Notion のページングで同じページが 2 回返ることがある。id で重複を落とす。

## 5. 先行タスク（依存）

- `先行未完了数 > 0` ＝ 先行待ち。先行待ちのタスク自体の操作は不可（先行から順に完了するか、チェーンごと AI に任せる）。
- **依存は自動では結ばない**。結ぶのは人（シートの「先行タスクを選ぶ」、同じ PJ の未完了から複数選択）か、夜間棚卸しの提案を人が見直しタブで確定したとき。間違った依存は後続を操作不能にする。
- 自分自身・循環は拒否。
- 未完了 3 件以上で依存 0 本の PJ には「順番未整理」バッジ。
- つながり（ガント／依存順）は「後続の期日 ＜ 先行の期日」の矛盾を赤で出し、「期日を先行に揃える」を 1 タップで。

## 6. WIP と状態

- `進行中`＋`人対応` の未完了（委任中と開始日が先のものを除く）を WIP として数え、上限（既定 10）を超えたらヘッダーに警告。
- `人対応` ＝ AI が「人の手が要る」で止めた印。人が手で付けるときは 🤖 の印も外す。人対応 を 🤖 で渡し直すと `進行中` に戻る。
- `待ち` ＝ GTD の Waiting For。相手を 1 行聞き、`説明` の先頭に `待ち (日付, PWA): 相手`。

## 7. 追加

- タイトルだけで起票。アイコン必須（既定 📥）、エリア既定（`QUICK_ADD_AREA`）、ソース `手動`、開始日 今日、実行環境 iPhone。残りは夜間の棚卸しが補完する。
- PJ 見出しから足したときは `関連プロジェクト` を付け、その PJ に他の未完了があれば「先行を選ぶ」ボタンを出す。

## 8. 取り消し

- 1 タップ操作には必ず ↩ を付ける。操作前の値（完了・期日・開始日・ステータス・担当・説明・AI処理開始・関連プロジェクト・先行タスク）を端末に控え、`POST /api/tasks/:id/restore` で渡された列だけ戻す。最大 20 件、端末ごと。
- 🤖 に投げる操作と「未完了に戻す」は対象外。

## 9. 見直し（一問一答カード）

機械的に作れる問いだけを 1 問 1 画面で出し、理由が要るものは AI チャットへ逃がす。

| 種類 | 元 | 答え |
|---|---|---|
| 未決 | Decisions 状態≠決着・開始日が来ている | 着手する／棚上げ／やめる → 決着（決定・決定日・結論）。今は決めない → 提示済み＋提示日 |
| PJ クローズ候補 | 未完了 0・完了 1 以上の PJ | クローズ（ステータス＝完了＋Decisions に決着行）／まだ続ける（次のアクションを足す） |
| 繰越 3 回以上 | 説明の `[棚卸し滞留 繰越N回` | 見送りで完了／⭐ 今日の3つ／来週に |
| 検証待ち | 決着・検証日≦今日・検証結果 空 | 当たり／外れ／部分的／検証不要（メモは 学び へ） |
| 習慣 | 計測方法 手動／半自動 で今日の記録なし | やった／やらなかった → Habit Log |
| 依存の提案 | 種別 `依存案` | 結ぶ（日程も置く）／結ぶだけ／結ばない |
| 日程の提案 | 種別 `日程案` | この日程にする／置かない |

## 10. やらないこと

- タスクの編集画面、Roles / Projects の編集画面、Habits の定義変更
- 期日だけを動かす延期ボタン（締切は AI か Notion で）
- ネイティブアプリ化・通知常駐（欲しくなったら Decisions に起票して再検討）

## 11. 公開前の検査

- `node --check` は ESM の `.js` を素通りする。**`.mjs` に写してから検査**する。
- 秘密はファイルに書かない。`NOTION_TOKEN` / `APP_TOKEN` は Worker の secret。
- `sw.txt` の `kairos-vNN` を上げないと端末のキャッシュが入れ替わらない。
